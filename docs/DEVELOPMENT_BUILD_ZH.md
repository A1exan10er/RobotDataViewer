## 使用

打开 episode，选择 **显示估算力**。第一次计算完整的传感器轨迹并自动保存，
结束后点击播放。再次打开相同录制数据时直接读取完整结果，不启动力推理。
界面显示已保存数量、复用数量和实际计算后端；保存失败时仍可播放已算出的值，
并明确提示导出保留。新增 **自动选择 / 优先 GPU / CPU**，只影响尚未计算的数据。
删除该 episode 的保存结果后再启用力显示，可重新计算。

- 原生启动器：结果保留至手动删除，默认目录见 [原生使用指南](NATIVE_FORCE.md)。
  初次启动复制旧缓存中有效的结果，不修改稳定版旧缓存；不再因 256 MiB LRU
  容量自动淘汰已完成结果。
- 纯 HTML：同一浏览器 origin 下自动保存到 IndexedDB。浏览器清理、配额回收、
  隐私模式或移动 HTML 后可能无法复用。要长期留档或换电脑，请使用 **保存力数据**。
- 两种方式均核对视频内容 SHA-256、传感器、尺寸、帧数、时间戳、参考帧和模型身份。
  损坏结果单独重算，未完成/被取消的传感器不会冒充完整保存结果。原始录制文件只读。
- 批量离线准备仍可使用已有 `tools/force/prepare.py`，支持文件夹/TAR、
  `--episode`、`--sensor` 和 `--provider gpu`。本版没有新增全数据集任务队列界面。

开发源码运行：

```sh
npm ci
npm run build
# 使用已安装原生依赖的 Python 环境；NVIDIA 环境需要 CUDA 版依赖。
python tools/native/launcher.py
```

本机另有已配置现有 CUDA 环境的本地入口：
`artifacts/development/Start Development Viewer.sh`。在项目目录执行：

```sh
bash "artifacts/development/Start Development Viewer.sh"
```

它运行当前开发源码和 `dist/viewer.html`，不替换稳定版程序。
这个入口依赖本机已有的 `artifacts/repair-venv` 与 `artifacts/force-profile-gpu`，
没有加入发行包；其他机器按 [原生依赖说明](NATIVE_FORCE.md) 配置环境。
纯 HTML 入口是构建后的 `dist/viewer.html`。

## GPU 与数值行为

GPU 模式把精确 DeepFlow 预处理从最多两路提高到最多四路，遵守物理 CPU 核数预算，
并复用已经得到的灰度图。解码/预处理队列有界，不把整段视频解码到内存。
神经模型、FP32 精度、DeepFlow 算法、输入分辨率、逐帧计算和首帧参考均保持原样。

自动选择仍先检查数值一致性和速度；短任务可保留 CPU。优先 GPU 会对短任务也检查 GPU，
但不可用、精度不通过或更慢时仍退回 CPU，并显示原因。浏览器可用 WebGPU，否则使用 WASM；
本机的 CUDA 加速通过原生启动器运行。CUDA/DirectML/CoreML 的各平台可用性仍取决于运行包
和驱动，本轮没有宣称 Windows/macOS 硬件验收通过。

## 触觉去噪

按每个 episode、每个传感器开头约两秒的图像建立固定中位数参考和逐像素噪声估计。
短片段用现有帧，仍遵守原先至少八帧的采样目标。用户需确保开头为空载。
以最初八帧为参考，如果后续连续两帧出现成片的明显变化，
则在变化开始前结束基线采样，减少早期接触污染基线的机会。
这是图像启发式检查，不能证明“物理上未接触”；最初八帧已接触时仍可能形成有偏参考。

扣除噪声后、Gaussian 平滑前，移除极小的孤立响应区域，避免噪点被平滑扩散为可见亮斑。
基线不会随播放更新，因此持续夹持不会被逐渐吸收，前后跳帧也保持一致。
**显示全部变化** 可绕过该去噪，检查微弱响应与噪声；有效感知区域遮罩始终保留。
极小的真实变化也可能被孤立点清理抑制，不能据黑色热图断言没有接触。
此图像去噪不进入力估算模型，不改变力值。

## 验证记录

测试机器为 Linux、RTX 5060 Ti。结果与截图位于本地忽略的 `artifacts/`，
不随源码上传客户录制文件。

- `npm test`：15 个 Node 测试文件通过，包含完整身份键、存储不可用、
  空载噪声、早期持续接触、孤立噪点、微弱/持续响应和跳帧一致性。
- `npm run build`：TypeScript 检查和生产构建通过。
- Python 3.10 的 28 项回归测试通过：原子保存、写盘失败、旧缓存迁移、
  重启、删除、损坏数据、认证与每任务后端选择。`tools/native/check-engine.py`
  验证取消、精确重复帧复用、设备故障和非有限值时的 CPU 回退。
- 隔离 Chrome、禁用网络：三帧四传感器样本首次准备 22.788 秒，
  重载并重新选择录制后读取已保存力数据 0.106 秒，无模型资产加载或推理。
  人为损坏一个保存结果后，仅该传感器重算。计时从开启力显示起，不含打开录制的时间。
- 浏览器配额写入失败注入：四路已算力值继续可播放，显示未保存提示。
  原生启动器真实 CUDA 准备 48 帧测试数据耗时 5.438 秒；完全退出再启动后，
  四条轨迹从磁盘读取耗时 0.0028 秒，没有新建计算任务。
- 真实 episode 0157、四传感器共 2,432 帧：原 GPU 处理 53.789 秒，
  开发 GPU 处理 36.055 秒，减少约 33%。包含 Python/模型初始化的整进程耗时
  分别为 60.897 / 40.558 秒；顺序测量会受驱动/文件缓存和本机负载影响。
  逐帧力值与原 GPU 实现的最大差异为 **0 N**。
- 同一完整片段开发版 CPU 整进程耗时 160.059 秒，约为 GPU 的 3.95 倍；
  CPU/GPU 逐帧最大力值差为 0.0000378 N，通过 `0.001 N + 0.1%` 容差。
- 真实“离心管装盖”episode 0070：四路各取开头 60 帧基线；约第 2 秒四路响应均为纯黑，
  第 18.8 秒接触仍可见。增益切换、展开、显示全部变化和往返跳帧一致性通过；
  原始图像不受影响。
- 合成连续播放：6.200 秒实测窗口前进 6.200 秒，无缓冲等待采样，
  四路各更新 191 次，10/10 接触采样可见。该结果不代表所有分辨率与机器的帧率保证。

后续真实样本验收仍需要用户对触觉显示作主观检查；这些软件测试不代表传感器物理精度标定。
