# 机器人数据查看器

## 开发版启动器（1.6.0-dev.2）

开发包会显示桌面控制窗口。“打开查看器”可重新打开浏览器；“复制启动地址”
包含浏览器退出控制所需的认证信息。点击“停止并退出”或关闭启动器即可停止
服务，仅关闭浏览器标签页不会停止。再次启动同一安装目录会复用已有服务。
正在计算力数据时会请求退出确认，已保存的完整结果保留。
原生构建会在 `dist/` 同时生成带版本号的可运行目录和 ZIP。
以下 rc.3 发布说明保留旧版本操作方式。

查看录制数据和 USB 实时相机时，请选择发布页中实际附带的对应操作系统便携版 ZIP：`windows-x64`、`linux-x64`、`macos-x64`（Intel）或 `macos-arm64`（Apple Silicon）。运行环境已包含，使用者只需桌面浏览器；下载完成后无需安装 Python、Node.js、配置服务器或连接网络。四个平台包均已在两个发布站点提供，并通过重新下载校验。此版本仍为候选版本，以发布页验证记录为准。

1. 将 **整个 ZIP 完整解压** 到本机文件夹。
2. **启动查看器：** Windows 双击 **Start Viewer.cmd**；Linux 打开 **RobotDataViewer**，或右击 **Start Viewer.sh → 作为程序运行**；macOS 双击 **Start Viewer.command**。默认浏览器将自动打开；若未打开，请将启动窗口中的本机网址复制到 Chrome、Edge 或 Firefox。
3. 保持启动窗口开启。选择 **录制数据** 打开文件夹/TAR，或选择 **实时相机 → 全部启动** 并允许使用相机。
4. 使用结束后关闭查看器标签页以释放相机，再在启动窗口按 **Ctrl+C** 停止服务。

部分 Linux 文件管理器也支持双击 **Start Viewer.sh** 运行。如果双击将其作为文本打开，请选择 **作为程序运行**；必要时在 **属性 → 权限** 中允许作为程序执行。也可以直接打开包内的 **RobotDataViewer** 可执行文件。

所有文件和子目录须保留在一起，可以整体移动或重命名解压后的文件夹；不要只复制启动文件。启动入口随软件包分发，无需安装桌面快捷方式。分发给同事或客户时请保留许可声明与源码材料；录制数据文件夹或 TAR 请单独提供。

较小的纯 HTML 版 `RobotDataViewer.zip` 仍可双击 **viewer.html** 打开，但不含 localhost 启动器。检查实时相机时，建议使用对应系统的便携包，让浏览器通过本机网址请求相机权限。

请从 [GitHub 发布页](https://github.com/A1exan10er/RobotDataViewer/releases/tag/v1.5.0-rc.3) 或 [Gitea 发布页](https://git.neoteai.com/yangtianyu/RobotDataViewer/releases/tag/v1.5.0-rc.3) 选择实际附带的系统包：Linux x64、Windows x64、macOS Intel 或 Apple Silicon。以发布页附件与验证记录为准。

如果 **全部启动** 按钮不可用，表示当前页面不具备安全环境或浏览器未提供相机接口，此时尚未执行设备检测。请打开 **Start Viewer**（Linux 也可直接打开 **RobotDataViewer** 可执行文件），在桌面版 Chrome、Edge 或 Firefox 中访问启动器显示的 `http://127.0.0.1` 地址。直接打开 `file:` 文件能否使用相机取决于浏览器；普通远程 HTTP 页面无法访问相机。点击启动后若提示权限被拒绝，请在浏览器及系统设置中允许相机访问后重试。

修复版 **v1.5.0-rc.3** 对应提交 **b7c47bb8ae06e6e76d0189d205050c7e9199c38a**。同版本修复包通过 **BUILD.json** 标明构建提交与查看器校验值。请使用发布页的 **SHA256SUMS.txt** 和 **RELEASE-MANIFEST.json** 校验下载；附带的 repaired-source 源码包对应修复提交，GitHub/Gitea 自动生成的标签源码包仍为原始 rc.3 源码。

在 **录制数据** 中点击 **打开文件夹**，选择原始记录文件夹或包含多段记录的上级文件夹；也可以点击 **打开 TAR**，直接选择原始记录的 `.tar` 文件。在侧栏中选择记录并点击 **播放**，RGB 和触觉会并行准备并同步开始播放。

可以直接选择 `local-data` 文件夹。原始 TAR 文件无需解压或预处理。所有数据只在本机读取，可完全离线使用。

查看头戴相机数据时，选择完整的导出文件夹（例如 **T1E1**）或其 TAR 文件。左右眼视角、腕部视角、触觉响应和轨迹会自动一起显示；请保留其中的 `umi` 子文件夹，无需整理或转换数据。

拖动时间轴定位；使用速度菜单调整播放速度，或点击上一帧、下一帧逐帧查看。空格键切换播放与暂停，左右方向键逐帧移动。各面板均可展开。轨迹面板支持拖动旋转、Shift 拖动平移、滚轮缩放。展开“记录信号”可查看数值通道。

点击一次**播放**，RGB 与触觉画面将在所有可用通道就绪后同时显示并同步播放。准备期间时间轴保持在所选位置；点击**暂停**可取消等待中的播放请求。跳转和逐帧操作仍可使用，并会更新所有通道需要准备的位置。准备失败的通道会显示提示，其余通道就绪后仍可一起播放。返回已查看的片段时，可复用内存缓存中的标定结果；打开其他记录时缓存会清空。

每个**触觉响应**面板只显示一张响应图，保持传感器原始画面的方向。紫色经橙色至浅黄色表示图像响应逐渐增强；黑色表示未检测到响应或不在感知区域内。仅显示感知表面内部的变化。明亮弧线及其周围的保护带会被遮蔽为黑色，避免边缘移动主导显示；画面范围保持不变。未检测到弧形边界时，该面板保持黑色并显示提示，其他通道仍可使用。**弱–强**图例表示相对图像响应，并非实测力或压力。查看器使用起始 2 秒建立固定基线和逐像素噪声估计（可用时至少取 8 帧，短片使用全部帧），然后对变化进行平滑和着色。点击面板的显示设置（滑块图标），可在 1～16 倍之间调整显示增益（默认 10 倍），或开启**显示全部变化**，跳过去噪并显示感知区域内的细微差异和背景噪声，区域遮罩始终生效。伽马固定为 0.7。播放、跳转和展开面板始终使用同一基线与区域遮罩，持续的图像变化不会随时间消失。起始片段中的已有接触可能成为基线的一部分。若触觉图像没有可检测到的变化，查看器不会凭空显示接触。原始记录不会被修改。

查看器会自动使用完整的原始相机时间戳，支持 ARX5 训练数据中有意少一行的时间戳文件。“估算对齐”表示原始和训练时间戳文件均无法为每个视频帧提供有效时间戳，此时使用视频自身的时间信息估算。未记录触觉数值数据时，仍可查看触觉响应图。

点击语言按钮切换中英文。随时可打开其他文件夹或 TAR 文件。

请使用较新的桌面 Firefox、Chrome 或 Edge 浏览器。无需安装插件或额外的视频解码器。开始播放或跳转后，查看器可能短暂显示“正在同步”，以填充解码缓冲区。直接打开压缩包目前支持未压缩的 `.tar` 文件。

如果某个传感器的弧形边界难以检测，查看器还会检查所选文件夹或 TAR 中匹配的相邻片段，无需先手动打开这些片段。仅复用经过图像对齐验证的弧形几何；各片段仍使用自身的基线和噪声估计。将鼠标移到恢复提示上可查看参考片段。选择父文件夹或完整任务 TAR 可提供相邻片段。

## 可选力估算显示

力显示默认关闭。开启“显示估算力”后，查看器会复用匹配的已保存结果，或准备当前
片段的全部触觉帧。计算期间播放暂停，可能需要数分钟；可以取消或关闭此选项，
继续普通 RGB/触觉播放。准备完成后保持暂停，点击播放即可同步查看各传感器的
Fz（正向力）、剪切力大小（单位 N）及曲线。展开视图中也会显示数值。

点击“保存力数据”可分享 `*.rdv-force.json`。接收者可点击“导入力数据”，也可将
文件放在录制文件夹或 TAR 中。查看器按视频内容校验匹配关系，避免同名文件误配。
查看及浏览器计算均不需要 Python 或网络。浏览器计算需要将 `force-runtime.js`
与 `viewer.html` 放在一起；导入已有力数据时无需加载模型。

这些数值是模型估算，并非经过标定的实测力。首帧作为参考，可能已经包含接触；
模型本身也可能存在非零基线。增益及弧形边缘遮罩仅改变热图，不改变力估算。

## 原生力估算

对应系统的便携包也提供更快的原生力估算；通过 **Start Viewer** 启动，
并在使用期间保持启动器开启。
Python、OpenCV、ONNX Runtime 和 FFmpeg 已包含，无需安装开发工具。
仅将选中的触觉视频传给本机启动器；开启力估算时才加载模型。

完成的力数据保存在 256 MiB 磁盘缓存中，重启后仍可复用。工具栏显示占用量，
可以删除此片段或清除全部已保存结果；删除会关闭力显示，不会立即重新计算。
准备期间显示已用时、总帧进度和预计剩余时间；仍逐帧处理完整片段，完成后
保持暂停，点击播放即可同步查看。NVIDIA 运行库作为独立可选附加包提供。
详见 NATIVE_FORCE.md 与验证文档中的实测结果、支持平台及限制。

## USB 实时相机检查

选择“实时相机 → 全部启动”并允许相机权限。使用每张卡片上直接显示的选项，
选择腕部/环境（640×480，30 Hz）或触觉（640×360，30 Hz）用途。
点击铅笔按钮为每台相机命名，下方仍显示原始设备名。“采集设置”可自定义宽度、
高度和帧率（至少 1 Hz），填写后点击“应用”。界面分别显示请求与实际采集规格。
“恢复用途默认值”或切换用途会清除自定义规格。更改采集设置只重启对应的运行中
相机，并需要重新标定；重命名不会中断预览或标定。存储可用时，设置按浏览器
设备身份记忆，不按相机名称匹配。Firefox、Chrome 或 Edge 如果不能直接从本地
文件获得相机权限，可使用 localhost 启动器。原始图像始终可见；
移除接触后点击“标定”以查看触觉响应。“全部停止”关闭新设备自动预览。
操作、权限与候选版本验证范围见 [LIVE_CAMERAS.md](LIVE_CAMERAS.md)。

本次测试的 Linux Firefox 156 对此 USB 触觉相机支持不裁剪的 640×480/30 Hz，
但拒绝不裁剪的 640×360/30 Hz。请保持“触觉”用途，在“采集设置”中输入
**640 / 480 / 30**，点击“应用 → 启动”，再进行标定。用途与分辨率相互独立。
需要不裁剪的 640×360 预设时可使用 Chrome；查看器不会通过静默裁剪或缩放
将不支持的规格显示为成功。

本次修复验收中，Linux Chrome 155 和 Firefox 157 均通过原生启动器完成一分钟真实相机预览，并在退出实时模式时释放相机。Chrome 触觉校准通过；Firefox 需显式设置 640×480/30 Hz，本次校准提示“未找到感知区域”，但原始视频保持正常。Windows/macOS 已通过自动化启动和合成相机检查，真实相机硬件验收仍待完成。
