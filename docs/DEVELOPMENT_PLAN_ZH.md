## 1. 力值：一次准备、可靠保存、播放不推理

**已经存在的能力。** `src/force.ts` 已在启用力值时暂停播放，计算整段视频，保存完整的每帧 Fz 和剪切力大小。原生程序已有 256 MiB 磁盘 LRU，内存缓存为 32 MiB；`.rdv-force.json` 可导入、导出，也可随目录/TAR 自动发现。缓存匹配涉及视频内容 SHA-256、传感器、尺寸、帧数、时间戳、参考帧和模型/预处理身份。原生 CUDA、DirectML、CoreML 以及浏览器 WebGPU/WASM 均已有选择逻辑。

**实际缺口。** 纯 HTML 计算结果目前仅留在内存，重开需要重新计算或手动导入力值文件。原生结果在 LRU 淘汰或清理缓存后也不再保留。程序缺少清晰的“已准备并保存 / 命中缓存 / 未保存”状态和面向整个数据集的准备入口；有 GPU 不意味着启动的是 NVIDIA 运行包。

**本机与性能证据。** 本次主机查询确认 RTX 5060 Ti，8,151 MiB 显存，驱动 580.178.04。代码中的 ONNX 模型可在 CUDA 上运行，但 `Preprocessor` 的 CLAHE、DeepFlow 和张量准备仍用 CPU。不能只看 GPU 利用率判断整条管线是否正常。

历史实测（2026-09-29，见 [VALIDATION.md](VALIDATION.md)，不是本轮重新跑出的速度）：episode 0157 的四路共 2,432 帧，原生 CPU 总计 153.908 s，冷 CUDA 78.415 s；解压后的 NVIDIA 包在库已热时准备耗时 69.100 s。重启后四路缓存查询 7.281 ms、无推理，这个毫秒数不包括整个 Viewer 打开和视频哈希耗时。冷 CUDA 的推理累计 34.009 s，预处理任务累计 105.388 s；后者并行执行，不能与其他时间直接相加。

**建议实现顺序。**

1. 保留现有力值文件格式和原始视频只读约束，增加“准备当前 episode / 准备全部 episode”与取消、逐传感器进度、后端和保存状态。完整传感器结果原子保存；取消/失败后重试跳过已完成轨迹，不把部分轨迹当完整结果。
2. 原生程序提供持久“已准备结果库”，与可淘汰缓存区分，默认保留到用户明确删除。迁入现有有效缓存；空间不足时明确标示“本次可播放但未保存”，提供导出，不能谎称已保存。
3. HTML 增加 IndexedDB 缓存和存储能力探测，但不承诺在隐私模式、浏览器清理、配额回收、`file://` 或移动 HTML 文件后仍永久存在。原生启动器采用随机端口，持久性仍依靠原生磁盘库，不能依赖浏览器 origin。跨电脑/跨浏览器的可靠途径继续是可携带的 `.rdv-force.json`。
4. 任何推理前先查匹配的完整轨迹。内容、时间映射或模型/预处理版本变化时失效；旧 v1 文件继续可读。若以后改变解码或光流算法，必须显式更新管线身份，不能复用旧身份掩盖数值变化。
5. 在本机对原生 CPU / NVIDIA 包做相同解码输入的端到端对照，记录启动、视频哈希、传输、解码、预处理、推理、写盘、重启命中各阶段。优化重点是复用模型会话、减少重复启动和有界预处理流水线，然后再评估 GPU 预处理。
6. 保留 FP32、TF32 关闭、全部帧和现有精度检查。自动模式短任务可选择 CPU；显示原因。换用 CUDA Farneback、DIS 或其他光流并不等价于当前 DeepFlow，须作为独立实验管线，用接触判定和数值回归验证，必要时重新训练，不能静默替换。

验收：同一数据关闭程序、重开或切换 episode 后再次启用力值，不创建模型会话；内容不同而文件名相同不会误命中；模型更新、损坏文件、磁盘满、取消、GPU 失败均有明确行为。相同解码输入继续满足 `0.001 N + 0.1%` 的容差和接触判定一致性。提速数字以完整 episode 墙钟时间为准；不预先承诺固定倍数。

## 2. 触觉：空载黑底、保留真实接触、避免把静态接触擦掉

**现状。** 已有开头约两秒的逐像素中位数基线、99% 分位噪声、固定余量、Gaussian 平滑和感应区遮罩。默认增益 10×，弱噪声仍可能被放大。开头两秒可能已经接触物体，不能天然作为空载真值；固定基线也不能自动解决曝光漂移、机械振动和周期噪声。

**建议方案。** 默认“无可检测接触响应时黑底”，优先保留弱接触。保留原始查看/未过滤对照和灵敏度调节，但不修改源视频、力值输入或已计算的力值。

- 增加空载参考区间选择：自动建议稳定区间，用户可以指定已知空载区间；可靠性不足则显示“参考待确认”。不能把“变化小”直接解释为空载，也不能自动承诺从未知接触状态恢复绝对接触。
- 使用可靠空载帧建立固定逐像素噪声分布和坏点掩码。在接触外背景足够可靠时，估计全局亮度变化；不要默认减去全画面运动中位数，因为它也可能是真实整体剪切。
- 去噪采用局部噪声阈值、小连通域/孤立点抑制和有限时域一致性。阈值按感应区尺度与空载噪声标定，避免按固定像素面积删除所有微小接触。
- 接触进入/退出采用滞回，证据组合固定空载差分与局部形变。持续握住物体时，即使相邻帧几乎不变，接触仍保留；不按“帧间光流为零”清空。松开后回黑；不在接触中更新基线。
- 如果采用时域状态，按源帧索引计算并缓存接触状态，随机 seek 通过固定历史窗口/检查点重建；暂停、倍速、倒退和重复定位必须给出一致结果。
- `reference_codes/optiflow.zip` 包含 CPU 光流对比、连通域处理、正散度及活动门控，可作实验参考。其全局平移扣除、固定圆盘和阈值不能直接当作接触真值，也不能直接替换已验证的力值预处理。

验收资料应覆盖空载、光照漂移、震动、轻触、持续静态夹持、滑动、松开、开头即接触和损坏视频，并覆盖多传感器/多采集时段。合成空载和已知噪声场景要求输出全黑；真实样本统计误亮面积、误亮帧比例、弱接触漏检率和响应延迟，须保留原图人工复核。新数据没有独立接触标注时，只能证明视觉去噪改善，不能证明“黑色一定没接触”。

## 3. Ego / UMI 标定：当前资料能支持什么

检查范围为用户提供的 `Camera_Parameters_Documents` 目录。

**Ego 双目内部标定基本自洽。**

- `2uq2_parameters.json` 与 YAML 六组矩阵/向量完全一致。
- 旋转行列式为 1.0，`RᵀR-I` 最大元素误差约 `2.22e-16`；平移范数与声明基线完全一致，为 **75.0311 mm**。
- 文件报告双目 RMS **0.1183 px**、保留姿态预测 RMS **0.2022 px**。这些是文件中的统计值，本轮没有原始棋盘观测，无法重新计算。
- 文件明确写明最终对全部 30 组重新拟合，未做独立采集时段或实测尺寸验证，因此上述数值不等于毫米级精度保证。

**UMI 内参需要先复核覆盖范围和设备身份。**

- `intrinsics_LRCP.yaml` 报告训练 RMS **0.1991 px**、保留视图 RMS **0.1961 px**、30 视图；棋盘中心覆盖跨度仅为画面宽/高的约 **28.2% / 15.5%**。这个字段只描述中心跨度，不等于全部角点覆盖率。
- 对文件给出的 OpenCV fisheye 多项式作数值检查，径向映射在离光轴约 **76.0°** 开始不单调。在四角、四边中点及主点共 9 个压力测试点中，OpenCV 4.12.0 有 **5 个点**返回求解失败哨兵值。不能直接拿这组参数做全画面去畸变/射线投影。
- 这不证明中心可用区域也错误。需要实际镜头像圈/有效 ROI、原始标定图和独立边缘观测，才能判断失败位置是否属于有效画面；若属于有效区域，应重新拟合并检验单调性。
- YAML 的相机名称为 `LRCP U3-imx307`，而 UMI 规格书写 `SC233HGS`。应先核对设备序列号、镜头、图像裁切和文件归属，再用于 Viewer。

**Ego 也需要明确鱼眼的有效范围。** 其多项式在所检查的前向 0–90° 区间未发现非单调性，但相同矩形边界测试中的“反畸变后再畸变”最大回投误差约 **306 / 311 px**。OpenCV 4.12.0 反投影实现会限制极端归一化半径；有限坐标输出不代表求解准确。超广角资料不能简单用于普通针孔相机全画面投影。该结果是域/实现兼容性警告，不是观测重投影 RMS，也不能在未知有效 ROI 时认定整个标定无效。

**这些文件尚未提供完整公共坐标系。**

- Ego 的 `rotation_right_from_left` / `translation_right_from_left_m` 仅描述左右眼内部关系：`X_right = R_right_from_left X_left + t_right_from_left`。
- `UMI_Extrinsics.jpg` 是部分机械尺寸截图，不是包含坐标轴定义、原点和完整旋转/平移的光学标定。不能仅凭图中的距离和角度生成可信的 4×4 外参。
- `SC7U22.pdf` 是 IMU 规格，不能替代相机—IMU外参、时间同步或世界坐标轨迹。
- 现有 Viewer 会依据有效的 `umi_episode_start_relative_pose` 对齐双手；缺失时分屏显示。它读取 Ego 视频，但未读取 Ego 的世界位姿轨迹。
- 头戴 Ego 与手持 UMI 会独立运动，**不能用一组固定 Ego→UMI 外参对齐整个 episode**。固定的是每个设备内部的 camera/body/TCP/IMU 安装关系；设备之间的相对位姿随时间变化。

**可先开发的部分。** 加入可选 `*.rdv-calibration.json` 导入和检查，内部采用命名坐标系、米、明确方向的 `T_target_from_source`、设备身份、原始分辨率、畸变类型、有效 ROI 和标定来源/状态。未知边保留未知。旧数据不要求迁移；没有完整关系时保留独立视图，并显示“未对齐”。加入校准预览和畸变射线显示，不能把鱼眼视场伪装成针孔矩形锥体。

动态位姿以可选 `*.rdv-poses.json` 导入，包含设备 ID、源/目标坐标系、episode 毫秒时间戳、米制平移、明确 `xyzw` 次序的单位四元数及有效性。现有 UMI CSV 继续适配；缺失时段不虚构运动。显示姿态由公共坐标变换、对应时刻设备位姿及模型安装变换组合，不能把导入位姿重复应用已有 UMI 参考变换。

**补齐标定与验证的采集建议。**

1. 为每台 UMI 和 Ego 各眼确认序列号、镜头、分辨率、裁切/缩放、旋转/镜像、焦距设置、像圈及曝光；单纯缩放可相应调整内参，裁切/镜像必须记录完整像素变换。
2. 提供现有 30 组棋盘原图、角点/观测文件、板格尺寸实测值和角点布局。保留新的独立采集时段，不再把它并入拟合；增加靠近有效边缘、不同距离和倾斜的观测。
3. 测量 camera→body/TCP/IMU 的完整安装变换；有同步位姿与固定标定板时可采用 hand-eye 标定。左右 UMI 不默认共用同一内参或安装外参。
4. 为 Ego 提供带时间戳、质量标识的世界位姿轨迹；可来自经验证的视觉惯性定位/外部定位。UMI/Ego 若各有 SLAM 世界坐标，还需要共享静态标定板/标记或外部参考对齐这些世界坐标，并验证尺度、时间偏差和漂移。单时刻对齐无法消除后续漂移。
5. 用独立数据报告有效 ROI 内的重投影分布、双目极线误差、已知尺寸/距离误差和跨设备闭环误差。具体毫米/角度验收线需结合最终使用距离和独立真值定义；本轮不虚构物理精度。

重复检查命令（只读原始文件，JSON 写到忽略的本地 `artifacts/`）：

```sh
artifacts/repair-venv/bin/python tools/calibration/audit.py \
  /path/to/Camera_Parameters_Documents \
  > artifacts/calibration-audit.json
```

脚本使用现有 native 依赖中的 NumPy/OpenCV；其他机器可以在其对应 Python 环境运行。输出包含源文件 SHA-256、矩阵一致性、基线、单调性和明确坐标的压力测试点。**没有原始观测就不输出“物理精度验证通过”。**

## 4. 真实模型替换移动坐标轴

当前轨迹是 Canvas 2D 手工投影，不是已有的三维模型渲染器。建议在开发分支使用本地打包的 Three.js + GLTFLoader，保留轨迹、时间轴、旋转/平移/缩放和展开交互；默认隐藏设备自身的 XYZ 轴，调试时可开启。WebGL 不可用时保留现有轨迹视图并说明模型显示不可用。

硬件工程师可以直接按以下要求交付：

- **首选 glTF 2.0 二进制 `.glb`**：UMI 左/右设备和 Ego 双目整机，材质/贴图嵌入文件，不引用网络资源。
- 如果只有 CAD，提供 **STEP `.step/.stp`** 原件，由开发环节离线转轻量 GLB；OBJ+MTL+贴图也可转换。STL 仅作备选，因为缺少材质、明确单位和装配/关节关系。
- 真实尺寸，并明确原始单位。最终 GLB 使用米和 glTF 坐标约定；模型原点需与定义的 body/TCP 坐标关联，附模型坐标→body/TCP 的变换，不能靠视觉拖拽猜对齐。
- 在模型中标明/提供相机光心坐标、光轴方向、IMU 原点、TCP、触觉面和左右夹指。渲染坐标与 OpenCV 光学坐标分别转换。
- 若需要显示夹爪开合，将左右指爪与机身分为命名节点，提供关节轴、零位、行程、运动关系，以及记录的 gripper 数值是总开口还是单指位移。不提供这些数据时先展示真实外形的刚体运动。
- 首轮性能预算：每设备优先不超过约 50k 三角面、贴图不超过 2K、单 GLB 约 10 MB 内；这些是轻量交付目标，不是拒收原始 CAD 的硬性限制。

有 UMI 位姿即可先让 UMI 模型随时间运动。没有 Ego 世界位姿时，Ego 模型只能在独立设备预览中展示，不能放在公共场景中冒充已标定位置。CAD 未到时可用明确标注“示意模型”的几何体验证加载/时间轴，最终验收必须使用实际模型。

## 开发批次与验收

1. **结果持久化及批量准备**：原生库、浏览器能力检测、缓存状态和恢复；先验证“第二次零推理”。
2. **GPU 性能剖析及优化**：固定输入和模型正确性后优化瓶颈；GPU 失败可回退且不产生错序/缺帧。
3. **触觉去噪**：整理空载/接触样本，完成参考区间与确定性过滤，再对新样本盲测；持续接触不能消失，弱接触不得被一刀切抹掉。
4. **标定导入与模型渲染骨架**：变换方向、单位、姿态和时间对齐用合成案例验证；缺失/矛盾数据明确显示。模型就绪后验证尺寸、光轴、TCP 及指爪开合。
5. **真实统一场景验收**：收到完整外参、Ego 轨迹和独立验证数据后，验证同一空间下的 Ego/UMI 动态展示。此前可交付前四项，但不能宣称完整统一标定已经实现。

每批次保留旧 folder/TAR/companion 数据、离线运行、原始文件只读及播放同步的回归；CPU-only 机器仍可正常查看。稳定分支仅接受单独验证的维护修复。
